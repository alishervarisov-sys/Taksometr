# Процесс назначения курьера клиенту

## Визуальная схема

```
┌─────────────┐
│   Админ     │
│   Панель    │
└──────┬──────┘
       │
       │ 1. Нажимает на иконку PersonAdd
       │    рядом с курьером
       ↓
┌──────────────────────────┐
│  Модальное окно          │
│  "Назначить клиенту"     │
│                          │
│  Курьер: [Имя Фамилия]   │
│  ┌────────────────────┐  │
│  │ +992XXXXXXXXX      │  │ ← 2. Вводит номер телефона
│  └────────────────────┘  │
│                          │
│  [Отмена] [Назначить]    │
└───────────┬──────────────┘
            │
            │ 3. Нажимает "Назначить"
            ↓
┌───────────────────────────┐
│  Firebase Function        │
│  assignCourierToClient    │
│                           │
│  Проверки:                │
│  ✓ Админ авторизован      │
│  ✓ Курьер существует      │
│  ✓ Курьер не заблокирован │
│  ✓ Курьер онлайн          │
└───────────┬───────────────┘
            │
            │ 4. Формирует SMS на таджикском
            ↓
┌────────────────────────────────────┐
│  Payom.tj SMS Gateway              │
│                                    │
│  SMS (таджикский):                 │
│  "Салом! Шуморо бо хидмати ZaKi    │
│   муаррифӣ мекунем. Расонандаи мо  │
│   [Имя] (тел: [телефон]) барои     │
│   шумо таъин карда шуд..."         │
└────────────┬───────────────────────┘
             │
             │ 5. Отправляет SMS
             ↓
      ┌──────────────┐
      │   Клиент     │
      │ +992XXXXXXXX │
      └──────────────┘
             │
             │ 6. Получает SMS с контактами курьера
             ↓
```

## Детали реализации

### Frontend (Couriers.tsx)

**Новые элементы:**
- Иконка `PersonAdd` в колонке действий
- Состояния для модального окна:
  - `assignOpen` - открыто/закрыто
  - `assignCourier` - выбранный курьер
  - `clientPhone` - номер телефона
  - `assignLoading` - процесс отправки
  - `assignError` - ошибка

**Функции:**
- `handleAssignToClient(courier)` - открывает модальное окно
- `handleConfirmAssign()` - отправляет запрос в Firebase

### Backend (Firebase Functions)

**Функция:** `assignCourierToClient`

**Параметры:**
- `adminId` - ID администратора
- `courierId` - ID курьера
- `clientPhone` - номер телефона клиента

**Проверки:**
1. Администратор существует и имеет роль ADMIN
2. Курьер существует
3. Курьер не заблокирован (`isBlocked = false`)
4. Курьер онлайн (`isOnline = true`)

**Действия:**
1. Получает данные курьера (имя, телефон)
2. Формирует SMS на таджикском языке
3. Отправляет SMS через `sendSms()` → Payom.tj
4. Сохраняет запись в коллекцию `courierAssignments`

**Формат SMS:**
```
Расонандаи мо [Имя] (тел: [телефон]) барои шумо таъин карда шуд. 
Барои фармоиш додан бо ӯ тамос гиред. 
Барномаи ZaKi: https://clck.ru/3TuGb6
```

**Перевод:**
"Наш водитель [Имя] (тел: [телефон]) назначен для вас. 
Свяжитесь с ним для оформления заказа. 
Приложение ZaKi: https://clck.ru/3TuGb6"

## Обработка ошибок

### Frontend
- Пустой номер телефона → "Введите номер телефона клиента"
- Ошибка от Firebase → отображается в Alert

### Backend
- Не админ → "Only admins"
- Отсутствуют параметры → "courierId and clientPhone are required"
- Курьер не найден → "Courier not found"
- Курьер заблокирован → "Курьер заблокирован"
- Курьер оффлайн → "Курьер не в сети"
- Ошибка SMS → логируется, но не прерывает процесс

## База данных

### Новая коллекция: `courierAssignments`

Документы содержат:
```javascript
{
  adminId: string,        // ID администратора
  courierId: string,      // ID курьера
  courierName: string,    // Имя курьера
  clientPhone: string,    // Номер клиента
  createdAt: number       // Timestamp
}
```

Используется для:
- Аудита действий администраторов
- Статистики назначений
- Истории взаимодействий
