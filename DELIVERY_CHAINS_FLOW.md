# 🔄 Блок-схема работы "Дерево заказов"

## 📱 Сценарий 1: Курьер создает и выполняет цепочку

```
┌─────────────────────────────────────────────────────────────────┐
│                        КУРЬЕР                                     │
└─────────────────────────────────────────────────────────────────┘

1️⃣ Открывает "Дерево заказов"
   │
   ▼
2️⃣ Нажимает "Создать дерево заказов"
   │
   ▼ (создается DeliveryChain со статусом DRAFT)
   │
3️⃣ Добавляет заказы:
   │
   ├─► Выбирает тип доставки (стандарт/фиксированная)
   ├─► Вводит номер телефона клиента
   ├─► Вводит номер заказа
   └─► Повторяет для каждого заказа
   │
   ▼ (создаются ChainDeliveryItem со статусом PENDING)
   │
4️⃣ Изменяет порядок (drag & drop)
   │
   ▼ (обновляется sequenceOrder для каждого item)
   │
5️⃣ Нажимает "Запустить цепочку"
   │
   ├─► Cloud Function: startDeliveryChain
   ├─► Статус цепочки → IN_PROGRESS
   ├─► Первый заказ → IN_PROGRESS
   └─► SMS клиенту №1: "Курьер начал доставку"
   │
   ▼
6️⃣ Выполняет первую доставку
   │
   ├─► Едет по маршруту (трекинг GPS)
   ├─► Ждет клиента (если нужно)
   └─► Нажимает "Завершить и перейти к следующему"
   │
   ├─► Cloud Function: completeChainDelivery
   ├─► Рассчитывается стоимость
   ├─► Списывается комиссия
   ├─► Первый заказ → COMPLETED
   ├─► SMS клиенту №1: "Доставка завершена, сумма X"
   ├─► Второй заказ → IN_PROGRESS
   └─► SMS клиенту №2: "Курьер начал доставку"
   │
   ▼
7️⃣ Выполняет вторую доставку
   │
   └─► Повторяет шаг 6
   │
   ▼
8️⃣ Все заказы завершены
   │
   └─► Статус цепочки → COMPLETED
```

## 🖥️ Сценарий 2: Администратор создает и назначает цепочку

```
┌─────────────────────────────────────────────────────────────────┐
│                    АДМИНИСТРАТОР                                 │
└─────────────────────────────────────────────────────────────────┘

1️⃣ Открывает админ-панель → "Деревья заказов"
   │
   ▼
2️⃣ Нажимает "Создать дерево заказов"
   │
   ▼
3️⃣ Выбирает курьера из списка
   │
   ▼
4️⃣ Добавляет заказы:
   │
   ├─► Выбирает тип доставки
   ├─► Вводит номер телефона клиента
   ├─► Вводит номер заказа
   └─► Повторяет для каждого заказа
   │
   ▼
5️⃣ Нажимает "Создать и назначить курьеру"
   │
   ├─► Cloud Function: adminCreateDeliveryChain
   ├─► Создается цепочка со статусом IN_PROGRESS
   ├─► Первый заказ → IN_PROGRESS
   ├─► Push-уведомление курьеру: "Новая цепочка из X заказов"
   └─► SMS клиенту №1: "Курьер начал доставку"
   │
   ▼
6️⃣ Курьер получает уведомление
   │
   └─► Открывает приложение и видит активную цепочку
   │
   ▼
7️⃣ Курьер выполняет доставки (как в Сценарии 1)
   │
   ▼
8️⃣ Админ отслеживает прогресс в реальном времени
   │
   └─► Видит количество завершенных/оставшихся заказов
```

## 🔄 Жизненный цикл заказа в цепочке

```
┌──────────────────────────────────────────────────────────────┐
│                    ChainDeliveryItem                          │
└──────────────────────────────────────────────────────────────┘

   PENDING (Ожидает)
       │
       │ (предыдущий заказ завершен)
       │
       ▼
   IN_PROGRESS (Выполняется)
       │
       │ (курьер едет → ждет → доставляет)
       │
       ├─────────────┬─────────────┐
       │             │             │
       ▼             ▼             ▼
  COMPLETED      CANCELLED    (ошибка)
  (Завершен)     (Отменен)
       │
       │ (если есть следующий)
       │
       ▼
  Следующий заказ → IN_PROGRESS
```

## 💰 Расчет стоимости

```
┌──────────────────────────────────────────────────────────────┐
│                  Логика расчета стоимости                     │
└──────────────────────────────────────────────────────────────┘

ЕСЛИ deliveryType == "default":
   │
   ├─► Расчет по маршруту:
   │   ├─► Базовая стоимость (до 3 км)
   │   ├─► + за каждый км сверх базы
   │   └─► + стоимость ожидания (если > 5 мин)
   │
ИНАЧЕ (фиксированная цена):
   │
   └─► Берется fixedPrice из тарифа
       (например: "Ангишт" = 15 сомони)

   ▼
Списывается комиссия:
   │
   ├─► Проверяется индивидуальная комиссия курьера
   ├─► Если нет → берется глобальная комиссия
   └─► Комиссия = Стоимость × Процент / 100
   │
   ▼
Обновляется баланс курьера:
   │
   └─► Новый баланс = Старый баланс - Комиссия
```

## 🎯 Преимущества системы

✅ **Эффективность:**
   - Курьер выполняет несколько заказов за один выезд
   - Экономия времени и топлива

✅ **Гибкость:**
   - Изменение порядка доставок
   - Разные типы доставки в одной цепочке

✅ **Прозрачность:**
   - Клиенты получают SMS
   - Админ видит прогресс в реальном времени

✅ **Автоматизация:**
   - Автоматический переход к следующему заказу
   - Автоматический расчет стоимости
   - Автоматическое списание комиссии

✅ **Надежность:**
   - Локальный кеш (Room)
   - Синхронизация с Firestore
   - История всех операций
