# Проверка восстановления отслеживания на Android 14

Проверять на устройстве или эмуляторе API 34 с тестовым курьером и тестовым
заказом. Локальная сборка и JVM-тесты не подтверждают поведение ограничений ОС.

| Сценарий | Ожидаемый результат |
|---|---|
| Геолокация «При использовании», включить смену и начать заказ в открытом приложении | Работают оба трекера, появляются их постоянные уведомления |
| Заблокировать экран после успешного запуска | Координаты продолжают поступать; счётчик и маршрут сохраняются |
| Перезагрузить телефон с доступом «При использовании» | Нет падения или цикла запусков; восстановление ждёт открытия ZaKi |
| Разрешить геолокацию «Всегда» и перезагрузить телефон на смене | Оба нужных трекера восстанавливаются; при отказе ОС остаётся уведомление о восстановлении |
| Открыть приложение после отложенного запуска | Нужные трекеры возобновляются; уведомление о восстановлении снимается после регистрации GPS |
| Отозвать доступ к геолокации / отключить GPS перед восстановлением | Нет падения и ложного сообщения об успешном запуске; приложение объясняет необходимость GPS/разрешения |
| Разрешить GPS/геолокацию и вернуться в ZaKi | Запуск повторяется при возобновлении Activity; при оставшейся ошибке доступна кнопка повторного запуска |
| Push ADMIN_ORDER_UPDATED при работающем трекере | Обновляется состояние текущего заказа; новый GPS-поток не создаётся |
| Тот же push при отсутствующем трекере и закрытом приложении | Новый location-сервис не создаётся из push; данные синхронизируются, восстановление ждёт открытия приложения |
| Уничтожение процесса системой во время отслеживания | Обрабатывается null intent; восстанавливаются GPS, пауза и сохранённый маршрут, либо фиксируется управляемый отказ ОС |
| Переключение/пауза/возобновление двух заказов | Сохраняется расстояние каждого заказа; путь за время паузы/перерыва не добавляется к его стоимости |
| Повторные открытия главного экрана | Не появляются дополнительные GPS-потоки; счётчик не обнуляется |
| Персональный админский заказ: принять уже у точки забора, стоять на месте | Свежие координаты запускают этап «В пути к клиенту», двигаться ради записи маршрута не требуется |
| Админский заказ: находиться в 50 м от забора при погрешности GPS 60 м | Прибытие определяется, хотя точка с такой погрешностью не добавляется в километраж |
| Точка GPS внутри радиуса 200 м, но круг её погрешности пересекает границу | Переход ждёт уточнения; экран объясняет ожидание точности GPS |
| Нет координат / последняя точка старше 30 секунд / погрешность более 100 м | Нет ложного прибытия; подсказка сообщает об ожидании GPS вместо требования подъехать |
| Открыть заказ после перезапуска с устаревшей последней позицией у забора | Старая позиция не запускает этап; после свежего GPS происходит проверка прибытия |
| Завершить смену / выйти из аккаунта | Ненужные сервисы останавливаются; нет автоматического восстановления после перезагрузки |
| Войти администратором | Courier-трекеры не запускаются |
| Отказать в разрешении на уведомления | Нет падения; восстановление при открытии приложения и сообщение внутри приложения остаются доступны |

Принудительная остановка приложения пользователем — отдельный сценарий Android:
она не равнозначна уничтожению процесса системой и не проверяет START_STICKY.

В Crashlytics проверять отсутствие новых fatal событий по обоим location-сервисам.
Управляемые отказы сохраняются как non-fatal с полями `tracking_delivery_*` и
`tracking_shift_*`: источник, стадия, видимость Activity, API Android, обычное и
фоновое разрешения, GPS. Отсутствие падений проверять вместе с фактическим
поступлением точек и корректным расстоянием: одно перехватывание исключений
не доказывает работоспособность отслеживания.
